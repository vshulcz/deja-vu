Помнит ли ваш кодинг-агент предыдущие сессии?

на диске сохранено каждое слово, но новая сессия открывается с чистого листа

Короткий ответ — нет. Когда вы закрываете терминал или начинаете новый чат в Claude Code, Codex, Cursor, Gemini CLI или Qwen Code, окно контекста сбрасывается. При этом сам диалог, все запущенные команды и их вывод уже записаны на диск — просто ни один агент не индексирует и не ищет по этой истории сам.

Что каждый агент хранит на диске

АгентГде лежит историяЧто помнит новая сессия сама
Claude Code~/.claude/projects/**/*.jsonlCLAUDE.md и MEMORY.md (до 200 строк); прошлые .jsonl не читаются
Codex CLI~/.codex/sessions/**/*.jsonl(.zst)AGENTS.md; прошлые сессии доступны только через ручной codex resume
Cursorstate.vscdb (SQLite) и ~/.cursor/projectsправила .cursor/rules; поиск по старым чатам из нового чата не выполняется
Gemini CLI / Qwen Code~/.gemini/tmp, ~/.qwen/projectsGEMINI.md / QWEN.md; прошлые сессии изолированы

Что теряется при компакции (/compact)

Даже внутри одной длинной сессии, когда окно контекста заполняется и запускается компакция, суммаризация сохраняет около 77% архитектурных решений, но лишь 0,2% точных команд и флагов (замер на 43 реальных компакциях). Точная строка ошибки или флаг сборки почти всегда выбрасываются из сводки.

Как дать всем агентам память по уже существующей истории

Инструменты вроде claude-mem или Mem0 начинают записывать сессии только с момента своей установки и требуют LLM для суммаризации. deja-vu идёт другим путём: один Go-бинарник без LLM индексирует сессии, которые ваши 43 агента уже записали на диск за прошлые месяцы, и автоматически подаёт нужные решения через MCP и хуки.

curl -fsSL https://raw.githubusercontent.com/vshulcz/deja-vu/main/install.sh | sh
deja install --auto

После этого решение, найденное в марте в Codex, автоматически всплывает в Claude Code или Cursor, когда вы снова сталкиваетесь с той же ошибкой или тем же файлом.
