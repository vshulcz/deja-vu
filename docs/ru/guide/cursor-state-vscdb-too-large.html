state.vscdb в Cursor слишком большой: чем он забит и как его уменьшить

десятки гигабайт в одном SQLite-файле и способ освободить место, сохранив поиск по чатам

Типичный симптом: после перезапуска Cursor зависает на «Loading chats», новый чат долго думает на первом сообщении, а папка globalStorage занимает 30, 50 или 125 ГБ. Почти весь этот объём — один SQLite-файл state.vscdb.

Перед удалением чатов или переносом state.vscdb: в Cursor нет архива, поэтому любой удалённый чат пропадает навсегда. Запустите deja-vu (deja index) до очистки — deja прочитает state.vscdb в режиме только для чтения через sqlite3 и сохранит компактный локальный индекс всех диалогов.

Где лежит файл

# macOS
~/Library/Application Support/Cursor/User/globalStorage/state.vscdb
# Linux
~/.config/Cursor/User/globalStorage/state.vscdb
# Windows
%APPDATA%\Cursor\User\globalStorage\state.vscdb

Узнать, какие чаты занимают место (без риска для Cursor)

Закройте Cursor или выполняйте запросы с флагом -readonly:

sqlite3 -readonly state.vscdb "
SELECT substr(key, 1, instr(key, ':') - 1) AS kind, count(*),
       round(sum(length(CAST(value AS BLOB))) / 1e9, 2) AS gb
FROM cursorDiskKV GROUP BY kind ORDER BY gb DESC;"

Топ-15 самых тяжёлых чатов:

sqlite3 -readonly state.vscdb "
SELECT substr(key, 10, 36) AS chat, count(*) AS messages,
       round(sum(length(CAST(value AS BLOB))) / 1e6) AS mb
FROM cursorDiskKV WHERE key LIKE 'bubbleId:%'
GROUP BY chat ORDER BY mb DESC LIMIT 15;"

Как безопасно уменьшить размер

  • Удалите state.vscdb.backup, если он есть. Это устаревшая копия, которая часто занимает 10+ ГБ; при закрытом Cursor её можно безопасно удалить.
  • Удалите самые большие чаты через интерфейс Cursor или команду палитры Delete old chats…, затем запустите GC Agent KV Blobs.
  • Сохраните историю в deja перед очисткой:
curl -fsSL https://raw.githubusercontent.com/vshulcz/deja-vu/main/install.sh | sh
deja index
deja "pgbouncer"   # находит решение даже после удаления чата из Cursor
