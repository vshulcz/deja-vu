История сессий Codex CLI: где лежит, как читать и как искать

каждая сессия сохранена на диске, но codex resume умеет только листать список, а не искать по содержимому

Codex CLI сохраняет каждую сессию на диск. Через неделю после создания файлы сессий сжимаются в .jsonl.zst, поэтому обычный grep по *.jsonl перестаёт находить всё, что старше семи дней.

Нужен мгновенный поиск по всем сессиям Codex (включая сжатые .jsonl.zst и архивные)? deja-vu индексирует ~/.codex/sessions и archived_sessions за секунды: запустите deja --harness codex "ваш запрос" или откройте интерактивный поиск командой deja.

Где Codex хранит файлы

Всё находится внутри ${CODEX_HOME:-~/.codex}:

  • sessions/YYYY/MM/DD/rollout-<time>-<id>.jsonl — полный лог сессии. Через 7 дней Codex в фоне сжимает его в rollout-….jsonl.zst.
  • archived_sessions/ — скрытые через codex archive сессии в том же формате.
  • history.jsonl — только ваши промпты (без ответов агента и без вывода команд).
  • state_5.sqlite — SQLite-таблица заголовков и путей, которую читает пикер codex resume.

Чтение и поиск вручную

# последние 20 сессий из базы пикера
sqlite3 -readonly ~/.codex/state_5.sqlite "
SELECT datetime(updated_at, 'unixepoch', 'localtime'), substr(title, 1, 50), cwd
FROM threads WHERE archived = 0 ORDER BY updated_at DESC LIMIT 20;"

# поиск слова по свежим и сжатым сессиям
grep -l "pgbouncer" ~/.codex/sessions/*/*/*/rollout-*.jsonl
zstdgrep -l "pgbouncer" ~/.codex/sessions/*/*/*/rollout-*.jsonl.zst

Ранжированный поиск через deja-vu

deja index
deja --harness codex "pgbouncer prepared statement"   # ранжированный поиск с ID сессии
deja last 20 --harness codex                           # недавние сессии из любых папок
deja show <id>                                         # прочитать диалог
deja resume <id>                                       # команда для открытия в Codex

Если убрать флаг --harness codex, тот же запрос одновременно ищет по истории Claude Code, Cursor, opencode, Qwen Code и остальных агентов на машине.
