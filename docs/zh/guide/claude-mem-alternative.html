面向 Codex、Cursor 与 opencode 的 claude-mem 替代方案

直接从磁盘上已有的会话记录建立记忆，不需要模型去写摘要

claude-mem 是很多人接触到的第一个记忆插件，通过 hooks 监听会话，再让模型把发生过的事写成摘要留给下一次会话。

deja-vu 走的是另一条路：每一个编程智能体本来就已经把会话完整地写在磁盘上了；deja 直接按原样索引这些文件（自动脱敏密钥），再把相关的上下文交还给当前正在运行的智能体。没有模型去改写记忆，因此不需要消耗额外 Token 或 API Key，而且你安装之前几个月的历史在第一天就能直接搜到。

直接在现有历史记录上试用：brew install deja-vu && deja install --auto 约 15 秒即可索引本机已有的 Claude Code、Codex 与 Cursor 历史，可替代 claude-mem 或与它共存 —— GitHub 上的 vshulcz/deja-vu。

核心差异

deja-vuclaude-mem
记忆来源各个智能体已经写在磁盘上的会话文件，包含安装之前的所有历史从安装那一刻起通过 hooks 记录
谁来生成记忆无需生成：原样索引转录并自动脱敏密钥由模型总结每次会话（云端 observer、OpenRouter/Gemini Key 或 Anthropic 额度）

安装第一天的区别（Day Zero）

从安装后才开始往前记录的记忆工具，在装好的第一天是空的。在包含 19,195 个真实会话、100 个历史问题的 Day-Zero 基准测试中，deja 在 13.6 秒内建完索引即可直接回答历史问题。更重要的是，模型摘要往往会丢掉当时以为不重要、事后却最关键的细节：报错原文、编译参数、在跑通之前失败过的那条命令。deja 保留原始回合，因此 deja fix "<报错>" 能直接返回上次修好这个报错的命令，deja blame path:line 能定位写出这一行代码的那次会话。

切换或共存

brew install deja-vu
# 或：curl -fsSL https://raw.githubusercontent.com/vshulcz/deja-vu/main/install.sh | sh
deja install --auto

切换时，deja 还会直接只读解析 ~/.claude-mem/claude-mem.db，因此就算超过 Claude Code 30 天清理期的旧观察记录也不会丢。两者也可以同时运行；如果不想在会话启动时收到两份注入块，运行 deja install --all 即可只挂载按需调用的 MCP 工具。
