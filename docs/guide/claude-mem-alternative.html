A claude-mem alternative for Codex, Cursor and opencode

memory built from the transcripts already on disk, with no model writing it

claude-mem is the memory plugin most people meet first. It has 95k stars, and it now installs into Codex, Cursor, opencode, Windsurf, Antigravity, Grok Bot and OpenClaw as well as Claude Code. It watches sessions through hooks and has a model write summaries of what happened, which the next session gets back.

deja-vu takes the other route. Every coding agent already writes its sessions to disk; deja indexes those files as they are and hands the relevant turns back to whichever agent is running. Nothing writes the memory, so nothing has to be paid to write it, and the history from before you installed it is there on the first day.

The first day

Memory that records forward is empty on the day you install it. On the day-zero corpus, 19,195 real sessions and 100 questions whose answers are somewhere in them, claude-mem answers none, and that is its design rather than a fault: it has not recorded anything yet. deja builds its index over the same pile in 17.6 seconds and puts the right session first for 19 questions and in the top fifty for 65. The same table has six other tools that read existing history.

What a summary keeps

A summary is cheaper to inject and drops whatever the writer did not think mattered: the exact error text, the flag, the command that failed before the one that worked. deja keeps the turns, so deja fix "<error>" returns what was run after the same error last time, and deja blame path:line the session that wrote the line. The cost is the other side of it: the record is bigger than a summary, and lexical search misses paraphrases an embedding would catch. The benchmarks page shows where.

When claude-mem fits better

  • You want short observations curated for you rather than a searchable record, with semantic search on by default, and a model writing them is fine.
  • You started with coding agents recently, so there is little history on disk to read anyway.

Switching, or running both

brew install deja-vu
# or: curl -fsSL https://raw.githubusercontent.com/vshulcz/deja-vu/main/install.sh | sh
deja install --auto

--auto wires every agent it finds on the machine: the MCP server, session-start recall where the agent has hooks, and the first index, so sessions from months ago answer in the next session you open. Per-agent details are under Codex, Cursor and opencode.

The two do not get in each other's way. deja only reads the agents' session files and never touches ~/.claude-mem. Both add context when a session opens, though, so with both on the agent gets two blocks. If that is more than you want, deja install --all wires the same agents without the session-start recall, and deja answers only when the agent asks.
