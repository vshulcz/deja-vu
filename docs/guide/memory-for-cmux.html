Adding memory to cmux

shared transcript recall across Ghostty split panes, workspaces and cmux claude-teams

cmux (manaflow-ai/cmux) is a native macOS terminal built on libghostty for running parallel coding agents — Claude Code, Codex, opencode, Gemini CLI, aider — across vertical workspace tabs, notification rings, split panes, an embedded browser, and cmux claude-teams. Because each pane spawns a separate CLI session, closing a split or opening a fresh workspace tab drops everything the other splits learned.

same prompt before and after deja — local BM25 recall across past sessions on disk, zero LLM calls

Installing memory across cmux workspaces

deja install --auto

One pass wires the deja MCP server, shared deja-history skill, and native hooks into every installed CLI that you launch via cmux splits or cmux new-split automation — without colliding with cmux notifications, sidebar metadata, or Unix socket commands.

What carries across splits

  • Split and workspace handoffs: open a fresh workspace or switch from a Claude Code tab to Codex in the next pane, and pull recent edits, blockers, and decisions with deja orient, handoff, or automatic SessionStart context (parallel sessions).
  • Shared error repairs and file history: before editing a file or rerunning a failing command, hooks surface prior decisions and resolved errors recorded in other panes or before a context compaction.
  • Subagent and claude-teams runs: spawned sessions immediately query the single local BM25 store at ~/.cache/deja/index.db across all forty-eight agent formats (switching agents).

Underlying session formats

deja reads the native transcript files created inside each cmux pane: Claude Code, Codex CLI, opencode, Gemini CLI, and aider. Indexing stays local with credentials redacted before storage.

Repository memory & handoff

Share vetted project decisions and dead ends through git in .deja/memory.jsonl (deja repo candidates, deja repo add <id>). Entries are redacted on write, stored sorted with merge=union so parallel branches merge cleanly, and loaded for any teammate who clones the repository ({"activations":{"auto":{"repo":false}}} in the trust policy keeps them out of hooks). See repo memory.

Switching tools mid-task? Run deja handoff --to <agent> (or use handoff via MCP) to transfer the active session's goal, decisions, touched files, passed checks, and open work into another coding agent.
