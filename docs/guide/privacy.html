Privacy

what is indexed, what is stripped, what never leaves

deja indexes credential-bearing histories, so privacy is a first-order concern, not an afterthought.

What gets indexed

The conversation, and what the agent did while having it: the file paths its tool calls named, the commands it ran, the spans its edits replaced, and what its tools printed. That last part is why redaction matters — command output carries far more credentials than prose does — and every one of these paths goes through the same redaction pass as the conversation itself. Replaced spans are source code from your own files; they are stored so deja restore can hand work back, and they stay on the machine like everything else.

On every agent whose compaction deja captures (Claude Code, Codex, Qwen, Kimi, Grok, Cursor CLI, opencode, pi and the others in the compaction reference), the index also keeps a bounded packet of the working context captured just before a compaction — the task, conclusions, files and commands of that session, redacted like everything else, for at most 32 session/workspace pairs. It lives in the index manifest, is left out of sync exports, honours excluded projects and DEJA_RECALL=off, and deja forget removes it even before its session has been indexed. See compaction recovery.

Local by default

Indexing and search have no network path unless you turn on semantic search. The index and its usage sidecar never leave the machine.

Network access happens only when you run deja update, deja sync ssh, the doctor version check (which --offline disables), or deja embed (which sends redacted text to the endpoint you configured; once the semantic sidecar exists, each search and recall also sends its redacted query to that endpoint). At most once a day, a command typed at a terminal checks GitHub for the latest release number in the background; it sends no session data, never runs inside hooks or the MCP server, and DEJA_OFFLINE=1 or DEJA_NO_UPDATE_NOTICE=1 turns it off.

Redaction

Secrets are stripped at index time before anything is written — across the full message before any size cap, so a secret straddling a cap boundary cannot slip through:

  • Keys & tokens — API keys, JWTs, PEM/PGP private-key blocks, bearer and HTTP Basic auth, Authorization: Token headers, provider tokens, Slack/Discord webhook URLs, and scheme://user:pass@host URLs.
  • Assignments & prose — bare high-entropy values on the value side of an assignment or alone on a line, secrets split by ANSI color escapes (grep --color), and passwords stated in prose ("the admin password is …" when the value carries a digit or symbol).

Redacted output is what search, MCP recall, share and sync all serve; deja share also masks home paths (including encoded folder names like -Users-<name>-src) and emails.

Control what's kept

  • Exclude projects — ~/.config/deja/exclude patterns or DEJA_EXCLUDE_PROJECTS skip projects at index time and in sync export. Run deja index --rebuild to drop sessions indexed before a pattern was added. Exclusion rules take precedence over project aliases in ~/.config/deja/projects.
  • Exclude a whole store — a harness:<name> line in the exclude file (e.g. harness:opencode) or DEJA_EXCLUDE_HARNESSES skips that store entirely; deja sources and deja doctor report it as excluded.
  • Forget — deja forget removes sessions and records a tombstone so they don't come back on the next index; --dry-run to preview, --list to see tombstones, --unforget <id> to reverse one.
  • Audit & redaction report — deja stats --redaction shows what was masked per rule and harness; deja log lists recent recalls and injections, and deja log --last prints the exact digest most recently served.
  • Trust scopes — ~/.config/deja/policy.json controls which origins (local, imported, or imported:<group>) can activate on search, mcp and auto. For example, {"activations":{"auto":{"imported":false}}} (or DEJA_AUTORECALL_LOCAL_ONLY=1) keeps synced sessions searchable without auto-injecting them. Anything withheld on any path is also excluded from deja embed.
