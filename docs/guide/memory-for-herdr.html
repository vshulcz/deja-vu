Adding memory to herdr

cross-agent memory across detachable panes for Claude Code, Codex, Cursor, opencode and Grok

herdr multiplexes coding agents (claude code, codex, cursor, opencode, grok) inside persistent, detachable panes with live status tracking (working, blocked, idle), a socket API, and layout restore after detaching with ctrl+b q. What herdr does not unify is conversation memory: every pane still reads only its own agent's session log.

same prompt before and after deja — local BM25 recall across past sessions on disk, zero LLM calls

Wiring every harness herdr runs

deja install --auto

Because deja wires each underlying harness directly rather than sitting in the terminal PTY path, one command sets up recall across every tool installed on the machine — without changing your herdr keybindings, socket server, or pane layouts. You can also install targets individually (claude-auto, codex-auto, cursor-auto, opencode, grok-auto).

What panes share

  • Shared local index: as soon as any harness writes a turn to disk, deja indexes it into ~/.cache/deja/index.db (BM25 search with secret scrubbing) alongside all fifty-two supported agent formats.
  • Cross-harness handoffs: when a Claude Code pane hits a wall or finishes a submodule and you open Codex in another pane, deja handoff and SessionStart/UserPromptSubmit hooks carry over settled decisions and recent commands (session handoffs).
  • No duplicate mistakes across splits: error resolutions recorded in one pane flow back via fix and per-file history in every other pane working on the same repo (parallel sessions).

Format references for panes in herdr

herdr reads the standard native stores of each tool it launches: Claude Code, Codex CLI, Cursor, opencode, and Grok Build. Indexing and search stay on your machine, with tokens stripped during indexing.

Repository memory & handoff

Share vetted project decisions and dead ends through git in .deja/memory.jsonl (deja repo candidates, deja repo add <id>). Entries are redacted on write, stored sorted with merge=union so parallel branches merge cleanly, and loaded for any teammate who clones the repository ({"activations":{"auto":{"repo":false}}} in the trust policy keeps them out of hooks). See repo memory.

Switching tools mid-task? Run deja handoff --to <agent> (or use handoff via MCP) to transfer the active session's goal, decisions, touched files, passed checks, and open work into another coding agent.
