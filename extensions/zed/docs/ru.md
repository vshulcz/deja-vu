[deja](https://github.com/vshulcz/deja-vu) индексирует файлы сессий, которые кодинг-агенты уже записывают на диск — Claude Code, Codex, Cursor, opencode и ещё 48 инструментов — и отвечает по ним. Это расширение подключает такой индекс к панели агентов Zed как context server, позволяя искать прошлую работу даже за период до установки deja.

![Демонстрация deja-vu](https://raw.githubusercontent.com/vshulcz/deja-vu/main/assets/demo.gif)

## Что получает агент

Один инструмент `deja`, вызываемый с параметром `mode`:

| Mode | На что отвечает |
|---|---|
| `recall` | Сессии, где встречалась строка ошибки, имя функции, путь к файлу или флаг. |
| `context` | Полная сводка одной прошлой сессии, когда важен ход рассуждений. |
| `blame` | Сессии, в которых обсуждался файл, до его правки или удаления. |
| `fix` | Что запускалось на этой машине после такой же ошибки раньше. |
| `how` | Реальная команда сборки, тестов или деплоя из истории запусков здесь. |
| `orient` | Какие команды и файлы использовались в прошлых сессиях этого проекта. |
| `remember` | Сохраняет важное решение для последующего вызова. |
| `handoff` | Состояние другой сессии, чтобы продолжить работу с того же места. |

## Установка

Установите расширение из каталога расширений Zed. При первом обращении оно просит Zed выполнить `deja --version` и при успехе использует `deja` из `PATH` Zed. Иначе скачивает релизный бинарник `deja` в собственный каталог. Расширения работают в песочнице и не видят стандартные пути установки, поэтому если `deja` нет в `PATH`, с которым запущен Zed, путь нужно указать явно:

```json
{
  "context_servers": {
    "deja-context-server": {
      "settings": {
        "binary": "/opt/homebrew/bin/deja"
      }
    }
  }
}
```

`deja install --auto` тоже настраивает Zed и сразу записывает сервер в `settings.json` — более короткий путь, если CLI уже установлен. Оба варианта используют один идентификатор `deja-context-server`, а Zed хранит серверы по ID, поэтому при любом порядке установки останется ровно одна запись. Команда `deja uninstall zed` удаляет запись CLI.

Индексация и поиск полностью локальны: без сетевых запросов, а учётные данные очищаются при индексации.

## Память в репозитории и передача сессии (`handoff`)

Делитесь проверенными решениями и тупиковыми ветками через git в `.deja/memory.jsonl` (`deja repo candidates`, `deja repo add <id>`). Записи очищаются от секретов при записи, хранятся отсортированными с `merge=union` для беспроблемного слияния веток и подгружаются у каждого, кто клонирует репозиторий (`{"activations":{"auto":{"repo":false}}}` в политике доверия отключает подстановку через хуки). [Подробнее](https://vshulcz.github.io/deja-vu/guide/repo-memory.html).

Переключаетесь между инструментами посреди задачи? Выполните `deja handoff --to <agent>` (или вызовите `handoff` через MCP), чтобы передать цель сессии, принятые решения, затронутые файлы, пройденные проверки и оставшуюся работу другому агенту.
